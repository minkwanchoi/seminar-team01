# 오탐 유형 코드북 | v1

> 2026-11-26 확정 · 연습 표본 15건(`results/fp_sample.csv`)을 보고 만듦. 검증 표본(`results/fp_holdout.csv`)을 본 뒤 바뀐 정의는 v2로 따로 적고, v2는 다음 표본에서 다시 검증합니다(`docs/B_판정기록.md` J16).

**대상.** `judge.py`가 '오탐'으로 센 지적 한 건. 즉 Juliet의 정상 구역(`#ifndef OMITGOOD`, 약점을 고친 코드)에서 케이스와 관련 CWE로 나온 도구 지적입니다. 한 행은 지적 한 건이며, 케이스·도구·검사 수를 뜻하지 않습니다.

**읽는 범위.** 지적 줄이 들어 있는 함수 전체와, 그 함수가 쓰는 같은 파일의 보조 함수·매크로를 읽습니다. 고친 내용은 Juliet 주석(`FIX:`)과 실제 코드를 함께 보고, 주석만 믿지 않습니다.

| `fp_type`에 적을 값 | 포함할 때 | 경계 판단 |
|---|---|---|
| 위험 함수 이름 기반 | 도구가 함수 호출(`strcpy`, `memcpy`, `system`, `atoi`, `printf` 계열 등)의 **이름**만 보고 지적했고, 고친 코드에서는 그 호출이 안전함(크기·입력이 통제됨) | 메시지가 버퍼 크기·값을 언급하지 않고 함수 자체를 문제 삼으면 여기. 크기를 계산해 틀린 경우는 '값 범위 추론 한계' |
| 값 범위 추론 한계 | 고친 코드가 조건문·검사로 값을 제한하는데, 도구가 그 범위를 따라가지 못하고 같은 약점을 지적함 | 메시지에 구체적인 값·조건(`data>...`, 넘침 식)이 나오면 여기 |
| 선언 모양 기반 | 배열·변수 **선언**만 보고 지적함(예: 정적 크기 배열). 실제 접근은 경계 안 | 선언 줄을 지적했는지로 가름 |
| 다른 약점이 관련 CWE로 묶임 | 지적 자체는 실제 약점이지만, 케이스가 고친 약점과는 다른 약점이며 판정 규칙(J9, 상위·하위 관계)이 같은 약점으로 묶어 오탐이 됨 | 도구 지적이 코드상 맞는지 먼저 봄. 맞으면 이 유형. 이것은 도구가 아니라 판정 규칙의 한계 |
| 판단 못 함 | 위 넷 중 어느 것인지 근거가 부족함 | `reason`에 부족한 근거를 적음. 짐작으로 고르지 않음 |

**겹칠 때.** 한 지적에 유형 하나만 고릅니다. '다른 약점이 관련 CWE로 묶임'을 가장 먼저 봅니다(지적이 맞으면 오탐이 아니므로). 그다음 지적 줄이 선언인지, 메시지에 값·조건이 나오는지, 함수 이름만 문제 삼는지 순서로 가릅니다. 두 해석이 계속 가능하면 하나를 고르고 `reason`에 "경계 후보 ○○, 판단 근거 …"를 남깁니다.

**관점 주의.** CERT 같은 코딩 규칙은 함수 사용 자체를 금지하기도 합니다(예: `cert-env33-c`는 `system()` 호출을 금지). 이 코드북은 **케이스의 CWE 약점이 실제로 있는가** 관점에서 오탐을 봅니다. 규칙 위반으로는 맞는 지적일 수 있다는 점은 `reason`에 적습니다.

**작성 예시(연습 표본 9번).** 원본을 대상보다 작게(50) 고친 뒤 `strcpy(dest, data)`를 clang-tidy `insecureAPI.strcpy`가 지적함 → 위험 함수 이름 기반. reason: "원본 50바이트, 대상 50바이트로 넘치지 않는데 strcpy 호출 자체를 지적".

**판정 기록.** 사람 판정은 `human_fp_type`·`human_reason`·`human_by`·`human_at`, 에이전트 판정은 `agent_fp_type`·`agent_reason`·`agent_model`·`agent_at`에 적습니다. 검증 표본은 사람 판정을 먼저 적어 커밋한 뒤 에이전트에게 맡깁니다. 에이전트에게는 사람 판정 열을 보여 주지 않습니다.
