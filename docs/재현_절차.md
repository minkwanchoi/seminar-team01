# 재현 절차 (B 작업분, B7)

> 2026. 11. 21. · 팀원 B
> 저장소를 새로 받은 컴퓨터에서 B1~B6 결과(CWE 목록, 겹침 분석과 그림, Juliet 케이스, 정적 분석 판정)를 처음부터 다시 만드는 순서입니다. 각 단계가 끝나면 `git status`로 저장소에 있는 결과 파일이 바뀌지 않았는지 봅니다. 바뀌지 않았으면 같은 결과를 다시 얻은 것입니다.

## 0. 준비

| 필요한 것 | 쓰는 단계 | 비고 |
|---|---|---|
| Git, Python 3.12 | 전부 | 윈도 기준. macOS·Linux는 `.venv/Scripts/python` 대신 `.venv/bin/python` |
| 인터넷 연결 | 1·3단계 | MITRE CWE 파일(수 MB씩), Juliet(약 146 MB), PyPI 패키지 |
| WSL 우분투 24.04 (또는 리눅스) | 4단계 | 정적 분석 도구 세 개를 여기에 설치. 설치에 관리자(sudo) 비밀번호가 필요 |

```bash
git clone https://github.com/minkwanchoi/seminar-team01.git
cd seminar-team01
git switch b5-juliet        # B5·B6가 팀 저장소에 병합되기 전까지
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
```

## 1. CWE 목록 받기 (B1)

MITRE의 버전 파일을 받아 이 연구가 쓰는 뷰와 범주를 `data/cwe/vX.Y/`에 씁니다.

```bash
.venv/Scripts/python analysis/fetch_cwe.py 4.20
.venv/Scripts/python analysis/fetch_cwe.py 4.10
```

`fetch_cwe.py`는 원본 XML을 메모리에서만 읽고 저장하지 않습니다. 5단계의 `select_cases.py`와 `judge.py`는 프로젝트 루트에 `cwec_v4.20.xml.zip`이 있으면 그것을 쓰고, 없으면 MITRE에서 다시 받습니다.

## 3. Juliet 받고 케이스 고르기 (B5)

```bash
mkdir -p static-analysis/_juliet && cd static-analysis/_juliet
curl -L -o juliet-1.3.zip https://samate.nist.gov/SARD/downloads/test-suites/2017-10-01-juliet-test-suite-for-c-cplusplus-v1-3.zip
sha256sum juliet-1.3.zip    # ada9d7e1c323d283446df3f55bdee0d00bda1fed786785fe98764d58688f38eb
unzip -q juliet-1.3.zip
cd ../..
.venv/Scripts/python static-analysis/select_cases.py
```

- 결과: `static-analysis/juliet_cases.csv`(1,285개), `juliet_summary.csv`. CWE 4.20 기준
- `_juliet/`은 `static-analysis/.gitignore`로 빠집니다.

## 4. 정적 분석 도구 돌리기 (B5)

WSL에서 도구를 설치합니다(한 번만).

```bash
sudo apt-get update
sudo apt-get install -y cppcheck clang-tidy clang flawfinder build-essential
```

이 연구가 쓴 버전은 cppcheck 2.13.0, clang-tidy(LLVM) 18.1.3, flawfinder 2.0.19입니다(우분투 24.04 기본 저장소). 버전이 다르면 결과도 다를 수 있습니다.

WSL 안의 프로젝트 폴더에서 실행합니다.

```bash
python3 static-analysis/run_tools.py --all --name all-20261121
```

- 파일 1,304개 × 도구 3개 = 3,912건이고, 이 연구의 컴퓨터에서는 1시간쯤 걸렸습니다.
- 결과는 `static-analysis/_runs/all-20261121/`에 생기며 커밋하지 않습니다.
- 윈도 Git Bash에서 `wsl --cd`로 한글이 들어간 경로를 넘기면 경로를 찾지 못할 수 있습니다. PowerShell에서 `wsl -d Ubuntu-24.04 --cd "<프로젝트 경로>" -- python3 static-analysis/run_tools.py ...`로 실행하거나, 영문 경로에 저장소를 받습니다.

### 검증 기록 (2026-11-21)

같은 컴퓨터(윈도 11, WSL2 우분투 24.04)의 별도 폴더에 `git clone --branch b5-juliet`로 포크를 새로 받아(커밋 2a0d2e9) 위 순서대로 돌렸습니다.

| 단계 | 한 일 | 결과 |
|---|---|---|
| 0 | 새 가상환경에 `requirements.txt` 설치 | 이 연구 때보다 새 버전(pandas 3.1.1, matplotlib 3.11.2)이 설치됨 |
| 1·2 | `fetch_cwe.py` 4.20·4.10, `overlap.py --all-versions`, `compare_versions.py`, `plot_overlap.py` | `data/cwe/versions.csv`의 받은 날짜(`retrieved`) 열만 바뀜. 겹침 CSV와 SVG 그림 5개는 바뀌지 않음 |
| 3 | Juliet은 다시 받지 않고 이미 받은 zip을 복사(SHA-256 같음), `select_cases.py` | `juliet_cases.csv`(1,285개)·`juliet_summary.csv` 바뀌지 않음 |
| 4 | WSL에서 `run_tools.py --all` | 3,912건, 컴파일 오류 169건(원래 실행과 같음) |
| 5 | `judge.py`, `sample_fp.py` | `results/` CSV 6개 바뀌지 않음 |

검증하면서 고친 것: 저장소를 깊은 폴더에 받으면 Juliet 파일 경로가 윈도의 경로 길이 제한(260자)을 넘어 `judge.py`가 파일을 읽지 못했습니다. 긴 경로 접두어로 읽도록 고쳤습니다(`judge.py`의 `read`). 그 밖의 단계는 고치지 않고 그대로 돌았습니다.

확인하지 못한 것: Juliet을 인터넷에서 새로 받는 단계(3단계의 `curl`), 다른 사람의 컴퓨터, macOS·리눅스 데스크톱.
