## 2. 제도별 정리

### 2.1 매뉴얼 신뢰성시험 보안약점 점검 목록 44개 [2차]

- **출처:** MDS인텔리전스(정적분석 도구 CodeSonar 국내 공급사) 기술노트, 2026.02.20 게시. 본문에 "방위사업청 무기체계 소프트웨어 개발 및 관리 매뉴얼 원안(부록)" 표를 이미지로 실음.
- **내용:**
  - 매뉴얼이 2022.12.2자로 개정되면서 기존 CWE-658·659·660 점검에 보안약점 점검 목록 44개가 추가됨.
  - 44개 모두 CWE 번호로 되어 있음.
  - 표의 "중복여부" 열에 O가 25개 있음. 기존 세 뷰와 겹친다는 뜻으로 보임 [추정].
- **검증:** 44행 모두 출처 이미지와 한 줄씩 대조함.
- **인용 방식:** 매뉴얼 별책(2020)에 발췌 시 방위사업청장 승인 조항이 있으나, 학술 인용 기준(저작권법 제28조·제37조)에 따라 분석에 필요한 최소 범위(CWE 번호와 중복여부 표시)만 출처를 밝혀 인용합니다. 목록은 제2022-6호(2022.12.2.)에서 추가되었고 현행본은 제2024-6호(2024.12.26.)입니다. 현행본 원문은 확인하지 못했으며, 2025년 4월 업체 교육자료도 제2022-6호의 44개를 기준으로 해 목록이 유지된 것으로 추정합니다.
- **남은 점:**
  - 모아소프트 교육 안내는 이 개정을 "제2022-6호"로 적음. 현행 제2024-6호에서 목록이 바뀌었는지는 원문 확인이 필요함 [미확인].
- **분석에 준 영향** (`analysis/overlap.py`):
  - 매뉴얼 44 ∩ 행안부 49 = 33개, Jaccard 0.46. 44개 목록의 상당 부분이 행안부 목록과 같음.
  - O 표시 25개 중 9개는 CWE 4.20의 세 뷰에 없음. 매뉴얼이 예전 CWE 버전을 기준으로 한 흔적으로 보이며, 제언 ③(기준 버전 현행화)의 근거가 됨.

### 2.2 무기체계 SW 보안성시험 [2차, 논문]

- **근거:**
  - 매뉴얼(2018 논문 시점 방위사업청 예규 제161호, 2016.7)
  - 상위 규정 「무기체계 소프트웨어 개발지원에 관한 규정」(2016.10 시점 훈령 제327호)
- **적용 대상:** 전장관리정보체계(C4I 등)로 한정됨.
- **판정 방법:** 행안부 「SW 개발보안 가이드」 준수 여부를 국정원 CC 인증을 받은 진단 도구로 판정함.
- **한계 지적:** 국방기술품질원 저자들의 논문은 대상이 좁고 기준이 웹 중심이라 내장형 무기체계에 맞지 않는다고 지적함.
- **판단:** 별도 목록이 아니므로 행안부 49 집합과 같음. 현행 2024판에도 남아 있는지는 [미확인].

### 2.3 신뢰성시험 정적시험의 코딩규칙 검증 [2차, 논문]

- **언어별 규칙:**

| 언어 | 규칙 |
|---|---|
| C | MISRA-C:2012 |
| C++ | MISRA-C++:2008, JSF++ |
| C# | .NET 코딩 컨벤션 |
| Java | Oracle Code Conventions |

- 사업관리회의에서 조정할 수 있음.
- **판단:** 부분적으로만 매핑할 수 있음.
  - MISRA 규칙과 CWE의 공식 1:1 대응표는 없음 [추정]. MISRA 전문도 유료임.
  - Java·C# 컨벤션은 유지보수성 규칙이라 CWE로 매핑할 수 없음.
  - 정량 비교에서는 빼고 정성적으로만 서술함.

### 2.4 국가 정보보안 기본지침 제27조 (소프트웨어 개발보안) [2차]

- **내용:** 국정원 지침(2020.7.1 개정)으로, 다음 두 가지를 규정함.
  - 정보시스템 개발 시 행안부 고시 「행정기관 및 공공기관 정보시스템 구축·운영 지침」 제50~53조를 따름.
  - 감리 등을 통해 보안약점을 진단함.
- **판단:** 독자 목록이 없고 행안부 49와 같음. 국방부 기관에도 적용되는 것으로 보이나 [추정], 국방 특례가 있는지는 [미확인].

### 2.5 국방 정보화업무 훈령 [부분 확인]

- 국방부훈령 제2946호(2024.7.17 일부개정)로 검색됨 [2차]. 유효기간 조항이 있어 현행 여부를 다시 확인해야 함.
- 훈령 안에 보안약점 진단 조항이나 국방부 독자 목록이 있는지는 원문을 열지 못해 [미확인].
- 공개 자료에서 독자 목록은 찾지 못함. 행안부 49를 다시 쓸 가능성이 큼 [추정].

### 2.6 보안대책 검토·보안측정 → K-RMF로 전환 중 [2차, 논문]

- 국방사이버안보훈령은 대외 비공개 규정임.
- 「국방 사이버보안 위험관리 지시」에 따라 보안계획서 검토와 보안평가를 받으면 보안대책 검토·보안측정을 받은 것으로 봄.
- **판단:** 비공개이고 보호요구사항 중심이라 CWE 매핑은 불가. 팀원 A의 K-RMF 카드에 각주로 붙이는 정도면 충분함.

### 2.7 국방기술품질원 개발단계 SW 품질검증체계 [2차, 논문]

- 운용단계 결함 DB에서 뽑은 체크리스트와 소스코드 구조분석으로 이루어짐.
- **판단:** 체크리스트가 비공개이고 결함 유형 중심이라 CWE 매핑은 불가.

### 2.8 국정원 보안적합성 검증 [2차, 보도]

- 정보보호제품의 보안기능을 검증하는 제도이며, 소스코드 보안약점 목록이 아님. CC·보안기능확인서와 같은 범주임.
- **판단:** CWE 매핑 불가.

### 2.9 해외 비교군

- **SEI CERT C** [추정, 일반 지식]
  - CERT C 규칙과 CWE의 대응이 규칙 페이지와 MITRE CWE 항목의 Taxonomy Mappings에 공개되어 있음.
  - C/C++ 무기체계와 가장 가까운 해외 비교군 후보임. 추가하려면 MITRE CWE 데이터의 Taxonomy Mappings 열로 자동 추출할 수 있는지 먼저 확인해야 함.
- **DISA Application Security and Development STIG** [2차]
  - V6R4(2025.9), 286개 항목. 항목이 NIST 800-53 기반 CCI로 되어 있고 CWE 번호는 없음.
  - SQL 삽입, XSS, 오버플로우 같은 취약점 유형 항목만 수작업으로 매핑할 수 있음.
- **NIST SP 800-53 SA-11** [2차]
  - 통제 본문에 CWE 목록이 없음. SA-11(1)은 정적분석 도구 사용만 요구함.

**우리 연구에 주는 의미**

1. **③ 상호운용성 정보보호 시험**
   - 기사에 따르면 관련 규정에 취약점 항목이 명시되어 있지 않습니다. 검증 유형이 행안부 개발보안 가이드의 7개 분류와 같아서, 기사는 시큐어코딩 가이드 항목을 기준으로 비교했습니다.
   - 따라서 정량 비교에서는 행안부 49 집합으로 대표할 수 있습니다. 다만 대상(타 체계와 연동되는 무기체계·전력지원체계)이 보안성 시험과 다르다는 점은 제도 카드에 적어야 합니다.
2. **④ 보안성 검증**
   - 내장형 SW까지 대상으로 삼는 점이 보안성 시험과 다릅니다.
   - 세부 항목이 확정되지 않았고, CWE가 아닌 오픈소스 취약점(CVE 성격)까지 포함해 CWE 정량 비교는 할 수 없습니다.
   - 2019년 이후 실제로 시행됐는지, K-RMF로 흡수됐는지는 공개 자료로 확인하지 못했습니다 [미확인]. 2.6에서 확인한 "K-RMF 보안평가를 받으면 보안측정 등을 받은 것으로 간주"하는 특례가 이 검증에도 적용되는지는 추가 확인이 필요합니다 [추정].
3. **같은 체계가 ①~④를 중복해서 받을 수 있습니다.** 기사 결론도 "모든 시험이 CWE를 준용하고 있기 때문에 동일한 취약점 항목을 가지고 중복하여 시험하는 경우"가 있다고 지적합니다. 이 연구의 문제 제기와 같은 결론이며, 선행연구로 인용할 수 있습니다.

**기사의 정량 비교를 우리 데이터로 다시 해 봄**

| | 기사(2019, CWE 3.2) | 이 연구(2026, CWE 4.20) |
|---|---|---|
| 신뢰성 시험 취약점 점검(658∪659∪660) | 136개 | 169개 |
| 행안부 시큐어코딩 가이드 | 49개 항목 | 49개 항목, CWE 61개 |
| 공통 CWE | **9개**: 119, 134, 416, 457, 476, 495, 496, 543, 676 | **16개**: 기사의 9개 + 95, 190, 209, 242, 246, 382, 502 |

- 기사의 공통 9개가 이 연구의 결과에 모두 들어 있어, 방법이 같으면 같은 결과가 나온다는 점을 확인했습니다.
- 늘어난 7개는 두 가지 이유로 생겼습니다.
  - **CWE 뷰 확대:** 뷰 크기가 136개에서 169개로 늘었습니다(예: 190, 502).
  - **원문 CWE를 모두 반영:** 행안부 항목의 1:N 참고 CWE를 모두 넣었습니다(예: 95, 242, 246, 382, 209).
- 같은 비교가 7년 사이에 9개에서 16개로 바뀐 것은, 기준 버전을 고정하지 않으면 중복 판단이 달라진다는 근거(제언 ③)가 됩니다.

## 3. CWE 기반이지만 공개되지 않은 목록

질문: "CWE 항목으로 시험하는데 목록이 공개되지 않은 것이 있는가?"

결론: **있습니다.** 다만 별도의 비밀 목록이 따로 있다기보다, **사업마다 확정하는 실제 점검 목록**이 공개되지 않는 구조입니다.

| 대상 | 알려진 내용 | 공개되지 않는 이유 | 상태 |
|---|---|---|---|
| 사업별 확정 취약점 점검 CWE 집합 (매뉴얼 신뢰성시험) | 도구가 지원하는 CWE-658/659/660 항목은 모두 적용하고, 지원하지 않는 항목은 대안·사유를 내고 사업관리부서·기술지원기관과 협의해 결정함. 결과는 체계개발실행계획서와 STP/STD에 기록 | 사업 산출물이며 공개 대상이 아님 | **[확인]** 매뉴얼 부록 7(2020) 원문 |
| 같은 내용(국방기술품질원 저자 논문) | "무기체계 대상 사업 별로 CWE 규칙을 선별하여 소스코드의 취약점을 점검" | 위와 같음 | **[확인]** 노시찬 외(2022) 원문 |
| 거짓 경보·예외 처리 결과 | 도구 오탐이나 기능상 불가피한 결함은 사유서를 붙여 협의로 거짓 경보 처리 | 사업별 협의 결과 | **[확인]** 노시찬 외(2022) 원문 |
| 매뉴얼 원문 자체 | 2022.12 개정(제2022-6호)으로 보안약점 44개 추가. 2025년 업체 교육자료도 여전히 이 판을 기준으로 함 | 별책(2020) 주의사항: 발췌·복사·복제 시 방위사업청장 승인 필요(부록 1 제안요청서 양식 예시에도 "복제/복사 및 배포 금지" 표기) | **[확인]** 표기 / 2024판 변경 여부 [미확인] |
| 도구사 CWE↔도구 규칙 매핑표 | 도구가 44개에 대응한다는 업체 주장. 매핑표는 요청 시 제공 | 업체 자료 | [2차] |
| K-RMF 보안통제항목 | 미국 RMF와 비슷한 구성 | "통제항목 수를 제외하고 비공개" (CWE 목록은 아님) | [2차, 논문] |
| 국방부·각 군·ADD·방산업체 자체 CWE 목록 | 공개 웹과 학술 DB에서 존재 증거를 찾지 못함 | 알 수 없음 | [미확인] |

**우리 분석에 주는 의미**
- 실제 점검 범위는 도구와 사업에 따라 공개 뷰보다 작거나 다를 수 있습니다.
- 그래서 이 연구의 결과는 "문서상 최대 요구 범위의 비교"입니다. 이 내용은 `B_분석범위와_한계.md` 1-1에 반영했습니다.
- "공개 목록 외에 N개 항목이 더 있다"고 정량으로 밝힌 문헌은 찾지 못했습니다.
