## 2. 영향 범위: 틀리면 어디까지 번지는가

- **B2 매핑이 틀리면** B3의 모든 수치, B4 페이지, B5의 케이스 선택(`select_cases.py`가 매핑을 읽음), 보고서 4장의 겹침 해석, 정책 제언의 "공통 핵심 목록" 후보가 함께 바뀝니다. 그래서 가장 먼저, 가장 여러 번 확인합니다.
- **B1 뷰 추출이 틀리면** 매뉴얼 C·C++·Java 뷰와 관련된 쌍(10쌍 중 9쌍)이 바뀝니다.
- **B3 계산이 틀리면** 숫자만 틀리고 입력은 그대로이므로, 다시 계산하면 바로잡힙니다.
- **B6 판정 규칙(관련 CWE 범위, 구역 기준, clang-tidy 대응표)이 틀리면** 탐지율과 제도별 충족도가 함께 바뀝니다. 입력인 B2 매핑과 B5 케이스 목록은 그대로이므로, 규칙을 고치고 `judge.py`를 다시 돌리면 바로잡힙니다.

## 4. 위험과 대응

| 위험 | 대응 | 상태 |
|---|---|---|
| 매핑을 한 사람(B)과 AI만 확인함 | 팀원 A가 매핑을 보지 않고 원문에서 번호를 다시 뽑아 항목별로 비교 | 미실시. `second_check` 열에 `미실시`로 표시 |
| 같은 AI에게 다시 물어 "확인"으로 착각 | 독립 확인은 다른 사람이나 다른 자료로만 인정(`data/README.md` 판정 열 설명) | 규칙으로 적음 |
| 매핑을 고치고 결과를 다시 만들지 않음 | `verify_overlap.py` 2단계가 저장 결과와 다시 계산한 값을 대조해 멈춤 | 적용 |
| 결과에 맞춰 기준값을 고침 | 기준값과 근거(`basis`)를 한 파일에 두고, 바꿀 때는 같은 커밋에서 이유를 적음 | 적용 |
| CWE 버전에 따라 수치가 바뀜 | 수치마다 CWE 버전을 함께 적고, 버전별 폴더로 따로 계산 | 적용(4.10·4.20) |
| 상위·하위 CWE를 펼치지 않아 겹침이 작게 나옴 | 보고서에 한계로 적음. 펼친 결과는 '탐색'으로 따로 표시할 계획 | 한계 문서에 적음 |
| 공개 목록만 비교함 | 결과를 "공개 요구 목록 사이의 관계"로만 해석 | `docs/B_분석범위와_한계.md` |
| 원문 PDF·강의자료가 저장소에 섞임 | `.gitignore`로 제외(`/*.pdf`, `Ref/`, CWE XML, `local/`) | 적용 |
| 정적 분석 결과를 도구 성능 평가로 오해 | "여러 제도 충족도의 예시"로만 해석한다고 B5·B6 문서에 적음 | 적용(`docs/정적분석_결과.md` 0절) |
| 판정 규칙을 결과에 맞춰 바꿈 | 규칙마다 정한 때를 적고, 결과 본 뒤 바꾼 규칙(J13)의 수치는 '탐색'으로 표시 | 적용. 다만 규칙을 문서에 미리 적지는 못함(`docs/B_판정기록.md` 2.1) |

## 6. 영향평가로 다시 보기

3주차 강의의 영향평가 틀(영향받는 사람, 사라지는 것/생기는 것, 틀리면 책임, 퍼지면, 끝까지 쥘 판단)로 B 작업의 결과를 다시 봅니다. 대상은 "CWE 번호로 시험 기준의 겹침을 재고, 한 번의 정적 분석이 여러 제도를 얼마나 채우는지 보는 방법"입니다. 아래 사실은 기획안과 결과 문서에서 가져왔고, 판단이 필요한 문장은 비워 두었습니다.
